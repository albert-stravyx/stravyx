Internal · Reference · Independent challenge

Keep the plan. Tighten ten points before live ingest.

Verdict: support with conditions. Cloud API + manual is still right. FlightHub 2 still later. No NestJS/MQTT until Phase 1B and privacy approval. Two blockers must be designed before live radio or auto-upload.

Reviewer Architecture-challenger (independent)
As at 16 August 2026
Does not change ADR 0005 direction
01What this review was for

An independent reviewer tried to break the plan: drones report to Stravyx (Cloud API); everyone else uses manual upload. They were not asked to agree. They were asked: where could two companies see each other’s jobs? Where could photos land on the wrong booking? Where are we promising something the spare tyre cannot actually do?

How to read a finding

Picture (shop-floor analogy) → problem → recommended fix → two alternatives → who decides.

Severity

BLOCKER — do not turn on live MQTT / auto-upload until designed. HIGH — smaller slice can ship; do not half-finish for customers. MEDIUM — shape the design now.

02The ten findings
Blocker

A-01 — Keep each drone company’s room private

Picture. Alex and Brooke must not share hotel keys. MQTT access lists are necessary but not enough — login, list-devices, and upload keys are ordinary web requests.

Recommended fix (S2)

Each ReOC gets its own logical Cloud API workspace. The server decides the room from the login token — never from a company ID typed in the URL. Moving a drone between companies is an audited handover.

Who decides

Yes. Per-company rooms vs accept shared-room risk.

Blocker

A-02 — The handset that asks for the upload key must own the aircraft

Picture. Photos for SN-123 should go only to that job. Controllers can be re-paired. Binding the aircraft at “allocated” does not prove this controller currently flies it.

Recommended fix (S2→S3)

Short-lived capture session: company + controller + aircraft + job. Upload keys write only into that session folder. The “upload finished” report carries the same session id.

Who decides

Yes. Approve the session model and how fresh pairing must be.

High

A-03 — Manual upload is a spare tyre, not a second sports car

Manual always delivers booking, accept, progress labels, and raw photos. It cannot deliver a live map pin. Never let “is the drone online?” change who wins or the price.

Who decides

Yes. Live-ops A promises live-map parity, or only completion + files?

High

A-04 — “Allocated” is planning, not “this flight is live”

Monday’s assignment to Thursday’s job must not lock the aircraft as the live flight forever. Keep planned assignment; use the capture session as the only lock for live upload and tracking.

Who decides

Yes. Must we support several future scheduled missions on the same aircraft?

High

A-05 — Winning the job must be all-or-nothing

First-to-accept is a race. Accept, status change, and Release must be one database transaction with an idempotency key. Nightly cleanup of half-written rows is unacceptable.

Who decides

No. Follows existing marketplace rules.

High

A-06 — One way to name a file in storage

Do not ship storage_path, s3_key, and provider + object_key as three ideas. Store a provider-neutral address from S0. Download links are always minted by our server.

Who decides

Yes. Which storage provider, and do we migrate or start on the final cupboard?

High

A-07 — “Upload finished” texts can get lost

Ignoring a duplicate postcard does not find a missing one. Keep a durable inbox and periodically walk the session folder. Closing a session includes “we expected these files.”

Who decides

No. Use inbox + folder scan.

High

A-08 — “Held” is not the same as “safe to open”

Quarantine today only means the customer cannot download yet. Land files privately, check type/size/magic bytes, hash, scan malware before Release.

Who decides

Yes. Formats, size limits, scanner, retention.

Medium

A-09 — Do not force manual to pretend it is a live drone

Split plugs: status reporter, file ingress, device connector, live position source. Manual implements the first two. DJI implements all four.

Who decides

Yes. Contract change needs Program Design (named in ADR 0005).

Medium

A-10 — We have not yet proved the bill

Write costs at 1 / 100 / 1,000 devices for our Cloud API vs a verified FlightHub Business quote vs manual-only. Keep FH2 deferred unless the numbers change Live-ops A.

Who decides

Yes. What cost/risk threshold lets us go past a pilot?

What we will not do

Trust a company id in a URL · hand out upload keys from last-paired · treat postcards as the only proof a file exists · let customers download held files before type/malware checks · invent fake live-drone data on the manual path · rank dispatch by device-online · start NestJS/MQTT/FlightHub before Phase 1B and privacy · change the recommendation.
