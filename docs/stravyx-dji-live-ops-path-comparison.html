Internal · Reference · Live-ops A

Drones report to our shop. If they cannot, the job still finishes by hand.

Recommended path: DJI Cloud API into Stravyx, plus a manual upload path for everyone else. FlightHub 2 is a later option for processed maps and 3D — not how we connect aircraft for the first live-ops slice.

Audience Founders, operators, anyone without jargon
As at August 2026
Authority ADR 0005
01Picture the shop

Stravyx is the marketplace: customers book a drone job, licensed operators tap Accept (first one wins), the customer sees one price, and files come back through Stravyx.

A drone still needs a radio-to-internet link so live progress and photos can reach that marketplace. The question is: whose cloud does the remote controller talk to?

In one sentence: drones report to Stravyx. If they cannot, the operator still finishes the job in Stravyx by hand.
02Recommended: Cloud API + manual
Pilot 2 (or a Dock) joins a Stravyx workspace. Live status comes into Stravyx. Photos land in Stravyx storage. The customer never needs a DJI account.

Why this is Live-ops A

Live-ops A only needs book → first-to-accept → fly → raw photos. Cloud API does that into Stravyx. Manual is the spare tyre so brand never changes marketplace fairness, and a server outage does not strand a job.

Example

Alex’s ReOC wins a roof job — he taps Accept first. On the remote he opens Pilot 2 and joins the Stravyx cloud. The customer watches Track Job. After landing, photos upload. Alex Releases. The customer downloads from Stravyx, not a DJI website.

Pros we want

One system of record: booking, price, and delivery stay in Stravyx.
Several remotes or docks can bind without FlightHub 2 device seats.
Non-DJI operators use the same customer journey.
If the live link is down, the job can still complete by hand.
Customers never need a DJI or FlightHub login.

Cons we accept

We run and pay for the device cloud (MQTT, STS, storage, monitoring).
We own security: each controller must only see its own company’s traffic.
APP 8 still needs a DPIA — DJI licence checks may still call DJI overseas.
Live tracking / auto-upload only on supported Pilot 2 / Dock hardware.
No FlightHub maps/3D, Analyzer, or Virtual Cockpit until we buy or build later.
03Other approaches (context only)
These are not how Live-ops A ships. They stay here so a new reader understands why the recommended path is Cloud API + manual.
Option Why someone might want it Why it is not Live-ops A
Deferred
FlightHub 2 as the home
 Familiar fleet screen; modelling / Analyzer / Virtual Cockpit in the box; less Stravyx MQTT if DJI already hosts. Two systems of record; per-device seats; extra APP 8 hops; still does not give us first-to-accept or Network Price.
Rejected for day one
Cloud API and FH2 both required
 Ready earlier for FlightHub-native fleets; some operators avoid picking one cloud. Double setup; two failure modes; we still host Cloud API and pay FlightHub; no extra win for raw photos.
Later track
Custom Stravyx app (MSDK)
 Branded HUD; some consumer DJI models; live instruments on the phone when internet is poor. Large native build; every operator learns a new app; supported Pilot 2 / Dock already reach us via Cloud API.
Later, not this path: FlightHub 2 Business only if Layer 2 maps/3D become a product we buy. MSDK is a parallel operator-app track (ADR 0001 / 0003), not the marketplace backbone.

Drones report to Stravyx (Cloud API). Manual upload is always available. FlightHub 2 and a custom MSDK app are later capabilities, not how we connect jobs to customers for Live-ops A.
